# 0003. 협상 조합 1개 고정 (TLS 1.3, X25519, TLS_AES_128_GCM_SHA256)

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
목적은 상태 머신과 키 유도의 정확성이다. 다중 암호군과 그룹 협상은 학습 목표와 무관하게 복잡도만 늘린다.
기간은 2~3주, 1인 개발이다.

## 결정
- ClientHello는 TLS 1.3, X25519, `0x1301`(TLS_AES_128_GCM_SHA256)만 제시한다. 서버가 제시하지 않은 값을 고르면 중단한다.
- signature_algorithms에는 검증할 수 있는 4종(`0x0403`, `0x0804`, `0x0805`, `0x0806`)만 제시한다.
- HelloRetryRequest는 감지 후 명시 에러로 종료한다.
- NewSessionTicket은 재조립만 하고 버린다. 세션 재개, TLS 1.2 이하, 서버 구현은 범위 밖이다.

## 대안
- 다중 암호군/그룹 협상: 단일 조합으로 학습 목표를 달성한다.
- signature_algorithms를 넓게 제시: 서버가 검증할 수 없는 서명을 고를 수 있다.
- HRR 재시도 구현: 대상 사이트가 X25519를 지원해 실익이 없다.
- 세션 재개 구현: 풀 핸드셰이크 이해가 우선이다.

## 결과
- 장점: ClientHello와 협상 방어가 단순하다. 서버가 고른 CertificateVerify 서명은 반드시 검증할 수 있다.
- 단점/감수한 점: X25519나 이 암호군을 지원하지 않는 서버와는 연결하지 못한다.
