# 0005. 미니멀 X.509 파서: 원본 DER 범위 보관, 원시 서명 검증

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
인증서 체인 서명, 만료, 이름(SAN)과 CertificateVerify를 검증해야 한다.
서명 대상 바이트 구성과 DER 파싱은 직접 하라는 제약이 있다(C3, N4). RSA-PSS, ECDSA-P256 서명 검증은 libsodium에 없다.

## 결정
- tbsCertificate와 issuer/subject는 파싱 후 재직렬화하지 않고 원본 DER 범위로 보관한다. 이름 비교는 바이트 비교로 한다.
- 서명 검증은 OpenSSL 원시 `EVP_DigestVerify`로 하고, 공개키는 직접 파싱한 SPKI에서 만든다.
- 신뢰 앵커는 PEM CA 번들(`--cafile`)이고 PEM/base64 디코딩은 직접 한다.
- 중간 CA가 없으면 실패한다. AIA 추적, OCSP/CRL은 하지 않는다. 와일드카드 SAN은 단일 레이블만 지원한다.

## 대안
- 파싱 후 재직렬화: 서명 불일치의 고전적 원인이다.
- `X509_verify_cert`: N4가 금지한다.
- AIA로 중간 CA 받아오기: 범위 밖이다. 서명, 기간, 이름 검증에 집중한다.

## 결과
- 장점: 서명 대상 바이트가 서버가 보낸 그대로라 재직렬화 오류가 없다.
- 단점/감수한 점: 중간 CA를 보내지 않는 서버는 검증에 실패한다. 폐기 여부는 확인하지 않는다.
